# Development and verification

Python 3.11+ on macOS/Linux. Use a virtual environment and install `.[dev]`. `make check` runs behavioral tests, independent MCP/schema integration, targeted lint, Markdown/SVG checks and repository privacy controls. `make check-package` builds a wheel/sdist and installs the wheel in a fresh environment outside the checkout; its smoke check verifies command, root selection, bundled skills/guides and typed output. Runtime dependencies are empty.

Generic skill resources are validated as frontmatter and checked for broken local references. SVGs are original code-native diagrams generated by scripts/render_assets.py; rerun `make assets` after changing the generator. Review rendered graphics for readability; no diagram is proof of a real provider action.

Tests create disposable synthetic workspaces. They cover concurrent reservations and readers, journal interruptions/conflicts, partial batches, byte changes, one-submit replay, limits, private bundle import/export and wheel-only resource resolution. Additional live provider or GUI evidence requires a separate authorized run.

GitHub CI uses pinned action commits and read-only repository permissions. It runs Linux/Python 3.11 and macOS/Python 3.14. Check the exact pushed head's results before claiming remote CI passed. No workflow publishes a package, changes visibility, deploys, or reads a real workspace.

The private local ledger and historical Git objects are not migration fixtures. An initial clean app commit starts generic history; retain personal audit history only in the private workspace/backups. Publication checks should examine tracked files, package members and reachable history, not merely .gitignore.

The [architecture review and evidence](REVIEW.md) records the independent reviewer scope, concrete fixes and verification limits.
