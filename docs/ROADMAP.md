# Product boundaries

The private preview includes the native engine/CLI, MCP server, ACP client, optional compatible model host, exact/semantic retrieval, source-preserving intake, reviewed context, selected documents/CVs, private transfers and local application views. Optional native runtime/model and desktop components install separately.

The priority is completing useful job-search work through agents: fewer repeated questions, exact packets, clear next actions, interrupted-work recovery and portable private context. Add a capability only when it removes a real manual step and has a bounded contract, source identity and recovery rule.

## Evidence to strengthen

- Native desktop acceptance on each OS, beyond compilation and a macOS window check.
- Task-specific local decision/retrieval calibration using explicitly approved examples; no automatic employment decisions from toy probes.
- Connector adapters that return canonical provider observations without becoming another state authority.
- Signed installers, optional-component binary distribution and upgrade/rollback UX.

## Separate future scope

Multi-host operation needs a new transactional coordinator/storage version and per-user authorization. Local file locks cannot synchronize machines. Flexible evidence remains readable while stable operations/relationships can gain relational storage through a deliberate migration.

Public registries, automatic updates, remote hosting, recording and multi-tenant accounts are separate owner decisions. A compatible transcription endpoint is an optional supplied-file input, not a built-in recorder.

Measure verified workflow completion, latency, model rounds, retries and cost in the host. Smaller JSON or local event counts do not by themselves prove cost savings.
